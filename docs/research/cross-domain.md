## Normalization construction contract

Use dimensionless illustrative activations, population moments (divide by reduction-set size M), and a positive explicit epsilon. Statistics are recomputed on the current input except BatchNorm inference. Affine parameters are fixed illustrative settings, not learned in this page.

For a reduction set S: μ = mean(x), v = mean((x−μ)²), q = mean(x²), RMS = √q. Centered normalization is z=(x−μ)/√(v+ε); RMS normalization is z=x/√(q+ε). Then y=γz+β for LN/BN/GN; use y=γz for RMSNorm to match the pinned implementation. A separate added bias could be shown only if explicitly labeled an extra operation.

Read [LayerNorm v1 §3, equations 3–4](https://arxiv.org/html/1607.06450v1) for per-case moments and feature gains/biases. Read [RMSNorm v1 §4, equation 4 and §4.1](https://arxiv.org/html/1910.07467v1) for removal of centering. Their idealized invariance statements need finite-epsilon qualification in the actual demo.

Read [BatchNorm v3 §3 Algorithm 1, §3.1 Algorithm 2, and §3.2](https://arxiv.org/html/1502.03167v3): training reduces batch and spatial positions per channel; inference uses population estimates stored from training. The page should use explicitly fixed illustrative stored values rather than imply that one batch is a trained running distribution.

Read [GroupNorm v3 §3.1 equations 1–7 and §3.2 Figure 3 implementation](https://arxiv.org/html/1803.08494v3): each sample reduces the channels in one contiguous group plus spatial positions. G divides C. G=1 matches all-channel-and-spatial normalization statistics, not arbitrary feature-only LN. Affine parameter sharing can still differ.

Pinned official implementation audit: [PyTorch v2.5.1 normalization.py](https://github.com/pytorch/pytorch/blob/v2.5.1/torch/nn/modules/normalization.py), LayerNorm/GroupNorm/RMSNorm classes; [native layer_norm.cpp lines 247–279](https://github.com/pytorch/pytorch/blob/v2.5.1/aten/src/ATen/native/layer_norm.cpp#L247) confirms RMSNorm denominator is sqrt(mean(square(x))+epsilon), with gain and no bias. [batchnorm.py](https://github.com/pytorch/pytorch/blob/v2.5.1/torch/nn/modules/batchnorm.py), BatchNorm2d, confirms biased training-forward variance versus unbiased variance in the running update. Avoid copying the ambiguous RMSNorm Python docstring formula; native implementation resolves it. Explicit ε=1e−5 makes page output reproducible independently of dtype-specific defaults.

## Independently derived fixtures and counterfactuals

These are arithmetic derivations for validation, not empirical training results.

- Vector x=[1,2,3,4]: μ=2.5, v=1.25, q=7.5. With ε=0, LN gives [−3,−1,1,3]/√5; RMSNorm gives [1,2,3,4]/√7.5. With ε>0 replace denominators explicitly. Shift all values +5: LN unchanged; RMSNorm changes (q=57.5). Keep ε and affine fixed.
- Positive scale x→2x: with ε=0, normalized output is unchanged for nonconstant centered input/nonzero RMS input. With ε>0, denominator effectively uses ε/4 after canceling scale; the difference is generally small, not zero. Use tiny x=[−0.001,0.001] and ε=1e−5 to expose it: LN/RMS output magnitude 1/√11; doubled input magnitude √(2/7). Negative scaling flips the un-affined normalized output.
- Constant x=[3,3,3,3] gives centered z=0; RMS z=3/√(9+ε). All zeros give z=0 for every method when ε>0. Nonuniform gamma/beta can destroy zero output mean and unit-like variance; affine output must not be described as standardized.
- Batch fixture [N=2,C=2,S=2], flattened N,C,S order: [1,3,10,14,5,7,18,22]. BN channel 0 reduces [1,3,5,7] with μ=4,v=5; channel 1 reduces [10,14,18,22] with μ=16,v=20. Change only second sample: first sample's training output changes; with fixed inference μ/v it does not.
- GN same fixture with G=2: sets are [1,3], [10,14], [5,7], [18,22]. Every set normalizes to [−1,+1] at ε=0. G=1 sample 0 μ=7,v=27.5; sample 1 μ=13,v=51.5. Changing sample 1 cannot alter sample 0 under GN. Use C=4 for a more instructive G=1,2,4 interaction.
- Validate affine indexing with unequal per-channel gains and offsets; validate invalid groups, shapes, non-finite inputs, and ε. For JS numerical stability, use centered variance rather than E[x²]−E[x]², which catastrophically cancels for large offsets. Only claim accuracy in the bounded UI range.

## Recent literature check and scope

Searched primary literature on 2026-11-01. [Gupta et al., Findings EACL 2026](https://aclanthology.org/2026.findings-eacl.20/) extends geometric discussion; [Guo et al., arXiv:2605.14521v1](https://arxiv.org/html/2605.14521v1), §2–4, studies conditions for folding centering into upstream layers. These are context, not replacements for the four definitions. They do not justify an unconditional claim that RMSNorm and LayerNorm are interchangeable on arbitrary vectors. Exclude learned optimization behavior, speed benchmarks, normalization placement, adaptive/conditional normalization, and automatic checkpoint conversion from this release.

Recommendation: normalization remains the strongest first article. Next: inference memory, then tokenization beyond language, for different mechanisms and immediate visual payoff.
